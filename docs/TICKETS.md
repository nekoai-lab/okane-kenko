# Tickets ─ Vertical Slice への分解

> `/to-tickets` 形式。SPEC.md を、単体で価値が出る最小の塊に切ったもの。
> 並べ方の原則：**H2（境界データの診断で「これなら動く」と感じるか）を、AIを実装する前に一度判定できる順序にする。**
> 版：v1.0（2026-08-17）

## 依存関係

```
T-01 算定エンジン ✅完了
  └→ T-02 アプリの器・デプロイ
        └→ T-03 入力ウィザード（保険以外）
              └→ T-04 現在の保険（3経路）★最大の離脱点
                    └→ T-05 結果画面 v1（AIなし・テンプレート文）  ◀── ここでH2の一次判定。立ち止まる
                          ├→ T-06 「分かること／分からないこと」＋次の一歩
                          ├→ T-07 AI言語化（プレースホルダ＋ストリーミング）
                          │     └→ T-08 ガードレール G-1〜G-6
                          ├→ T-09 計測イベント → 完走率・離脱率
                          └→ T-10 配偶者分の追加（世帯単位）
                                └→ T-11 運営レビュー画面
                                      └→ T-12 RAG（出典表示）
```

## T-01 ─ 算定エンジンとゴールデンテスト ✅ 完了

**価値**：金額を決めるロジックが確定し、以後の全部がこの上に乗る。事業の核。

- [x] 必要死亡保障額（支出／収入の内訳つき）
- [x] 医療保障の過不足判定
- [x] 遺族基礎年金・遺族厚生年金・中高齢寡婦加算
- [x] 世帯単位の診断と、世帯としての結論の畳み込み
- [x] 制度パラメータのYAML分離と有効期限チェック
- [x] ゴールデンテスト10世帯・19死亡ケース（**70件パス**）

**完了条件**：`npm test` が green。Python参照実装（`calc.py`）と1円まで一致。

## T-02 ─ アプリの器とデプロイ

**価値**：URLを開けば何かが表示される状態になる。以後すべての作業が「見える」ようになる。

- [ ] Next.js（App Router / TypeScript）を作成し、`src/calc` と `src/params` をそのまま取り込む
- [ ] `POST /api/diagnose` を作り、算定結果のJSONを返す（画面はまだ無くてよい）
- [ ] Vercel に接続し、**リージョンを `hnd1`（東京）に設定**
- [ ] DBは使わない（Phase A）
- [ ] CIでテストを走らせる（GitHub Actions）

**完了条件**：デプロイ先URLに `curl` で世帯情報をPOSTすると、GT-01と同じ結果が返る。

## T-03 ─ 入力ウィザード（S1〜S5・保険以外）

**価値**：人に触ってもらえる形になる。摩擦を実測できるようになる。

- [ ] S1 本人の生年・就業形態／S2 配偶者・子／S3 年収レンジ／S4 資産・生活費／S5 住まい・団信
- [ ] すべてレンジ選択。「答えたくない」「分からない」を正規の値として保持
- [ ] 生活費は「年収から推定」を選べる（推定根拠を表示）
- [ ] 団信に1行の説明をつける（知らない人が多い前提）
- [ ] 進捗インジケータ
- [ ] 入力状態をURLに保持して中断・再開できる（DBを使わずに US-03 を満たす）

**完了条件**：スマートフォンのLINE内ブラウザで崩れず、必須設問が12問以内で終わる。

---

## T-04 ─ 現在の保険（3経路） ★最大の離脱点

**価値**：H1の本丸。ここで全員が離脱するなら、境界データ診断そのものが成立しない。

- [ ] ① 証券の写真アップ（抽出は別のLLM呼び出しに分離。読めない項目は空欄にしてユーザー確認へ）
- [ ] ② 手入力（最小は「月額保険料の合計だけ」でも可）
- [ ] ③ 「分からない」でも先へ進める
- [ ] **保険1件ごとに被保険者（本人／配偶者）を必須にする**（混同すると誤って「減らせる」と言う）
- [ ] 原本画像は24時間以内に削除

**完了条件**：③を選んでも結果画面まで到達し、過不足判定が `pending` になる。

---

## T-05 ─ 結果画面 v1（AIなし・テンプレート文） ◀ ここで立ち止まる

**価値**：**AIが無くても価値が届くかを確認できる。** H2の一次判定がここでできる。

- [ ] 冒頭に結論（足りている／足す／減らせる／要らない）
- [ ] 支出・収入の内訳を因数分解して表示
- [ ] 金額はレンジで表示し、「概算・要精査」「算定基準日」「使用パラメータ版」を明記
- [ ] 制度改正の該当／非該当を明示
- [ ] 減らせる箇所を提示（無ければ「見つかりませんでした」と明示）
- [ ] 主要な前提（生活費など）を本人が動かせるスライダー ─ 「当社基準」と明示
- [ ] 説明文は算定結果を差し込む固定テンプレート

**完了条件**：n1インタビューでこの画面を見せられる。**ここでH2が怪しければ、AI実装に進まず設計に戻る。**

---

## T-06 ─ 「分かること／分からないこと」と次の一歩

**価値**：期待外れを防ぎ、診断のあとに手が動くようになる。

- [ ] 結果冒頭に「この診断で分かること／分からないこと」（家計全体は扱わないと先に線を引く）
- [ ] 減らせる側：現契約への減額依頼の手順（商品名なし）
- [ ] 足りない側：勤務先の団体保険の確認（窓口・受付時期つき）／未登録なら「選ぶ基準」にフォールバック
- [ ] 「もっと知りたい」ボタン ─ 押したときだけ「選ぶ基準」を開き、押下を記録
- [ ] 外部リンクは公的機関のみ。商品名・保険会社名・送客リンクを出さない

**完了条件**：外部リンクの棚卸しで、保険商品への導線が0件であることを確認（受入基準 A-4）。

---

## T-07 ─ AI言語化（プレースホルダ＋ストリーミング）

**価値**：説明が世帯の事情に寄り、「自分ごと」になる。

- [ ] プロンプトを静的（規則・出力スキーマ・用語辞書）→ 動的（算定結果・個別化指示）の順で組む
- [ ] **AIには数値を書かせず、`{{necessaryAmount}}` 形式のプレースホルダだけを置かせる**
- [ ] ストリーミングで逐次表示。クライアントがプレースホルダに算定結果を差し込む
- [ ] タイムアウト時は算定結果のみ表示して診断を成立させる
- [ ] 禁止語辞書はプロンプトに入れない（検査側で持つ）

**完了条件**：AIを止めても結果画面が成立する。1診断あたりのトークン実測が10円以内。

---

## T-08 ─ ガードレール G-1〜G-6

**価値**：「金額を作らせていない」ことを事後に立証できる状態になる。

- [ ] G-1 数値照合（チャンク単位。未知のプレースホルダや生の数値を検知）
- [ ] G-2 禁止語検査（商品名・勧誘表現・煽り表現・最上級表現）
- [ ] G-3 出典なしの制度言及を削除
- [ ] G-4 結論の一致検査
- [ ] G-5 過剰があるのに減らせる箇所が空なら再生成
- [ ] G-6 投資商品への言及を削除
- [ ] 不合格2回でテンプレート文にフォールバックし、レビューキューへ
- [ ] 恒久／暫定を台帳で区別する

**完了条件**：GR-01〜GR-07 のテストが全件パス（受入基準 A-2・A-3）。

## T-09 ─ 計測イベントと完走率

**価値**：H1が数字で判定できるようになる。

- [ ] 設問単位のイベント（表示・入力・スキップ・離脱・所要秒数）
- [ ] 完走率／設問別離脱率／「分からない」選択率／納得感スコアの集計
- [ ] 記録は擬名化ID＋レンジ値のみ（実額・氏名を出さない）

**完了条件**：完走率50%・「現在の保険」離脱率30%未満・納得感60%が、ダッシュボードで判定できる。

## T-10 ─ 配偶者分の追加（世帯単位）

**価値**：共働き世帯に世帯としての答えが返る。再訪の理由にもなる。

- [ ] 本人分の結果画面から「配偶者分を追加する」導線
- [ ] 配偶者の死亡ケースを算定し、世帯としての結論を1行に畳む
- [ ] 本人過剰・配偶者不足なら「世帯で見れば合計保険料を増やさずに解決できます」を表示（「付け替え」とは言わない）

**完了条件**：GT-01 で `rebalanceable` の表示が出る。

---

## T-11 ─ 運営レビュー画面

**価値**：すり抜けた事例を拾って禁止リストを育てられる。

- [ ] 算定値・AI出力・ガードレール判定・リトライ回数・フォールバック有無を1画面で
- [ ] レビュー結果の記録
- [ ] MVP期間は全件レビュー（違反率が2週連続0.5%未満になったら抽出レビューへ）

---

## T-12 ─ RAG（出典表示）

**価値**：制度の話に出典がつき、「思い込みで語っていない」ことが見える。

- [ ] 公的文書を知識ベース化（年金・高額療養費・傷病手当金・団信）
- [ ] 有効期間でフィルタしてから検索する（改正前の文書を引かない）
- [ ] 出典名＋年度＋URLを表示
- [ ] **商品情報は知識ベースに入れない**
