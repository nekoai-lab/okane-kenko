# Domain docs

エンジニアリングスキルがこのリポジトリのドメイン文書をどう読むか。

## 探索の前に読むもの

- **`docs/CONTEXT.md`** — 用語集（ルートの `CONTEXT.md` ではない）
- **`docs/ADR.md`** — 決定の記録。**単一ファイル**。着手する領域に関わる決定を読む

これらが無い場合でも、黙って進める（不在を指摘しない・先回りで作成しない）。

## 置き場所は固定 ─ 二重管理を作らない

このリポジトリは single-context だが、既定の配置ではない。

- 用語集は **`docs/CONTEXT.md`** の1ファイル。**ルートに `CONTEXT.md` を作らない**
- ADR は **`docs/ADR.md`** の1ファイルに追記していく。**`docs/adr/` ディレクトリを作らない**
- **`docs/CONTEXT.md` と `docs/ADR.md` は、人間の確認なしに編集しない**（CLAUDE.md「ドキュメントの置き場所」を参照）

`/domain-modeling` などが用語やADRを既定の場所（ルート `CONTEXT.md`・`docs/adr/`）に作ろうとしても、上の置き場所に従う。

## 用語集の語彙を使う

出力がドメイン概念を指すとき（チケット名・リファクタ提案・仮説・テスト名）、`docs/CONTEXT.md` の定義どおりの語を使う。用語集が避けている同義語に流れない。

必要な概念が用語集に無いときは合図：語を発明しているなら考え直す。本当に欠けているなら `/domain-modeling` 用に記録する。

## ADR と矛盾したら明示する

出力が既存の ADR と矛盾する場合は、黙って上書きせず明示する。ADR は `docs/ADR.md` の追記形式なので、該当する決定を特定して引用する。
