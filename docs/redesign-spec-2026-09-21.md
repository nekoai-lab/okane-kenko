## 1. コンセプト決定事項(不変条件)

- **主語は「人生の全リスク」**。死亡だけでなく、病気・けが(短期/長期)・就業不能/障害・失業を同じパイプラインで診る。
- パイプラインは3段で共通: **①何が起きるか → ②公的なしくみがどこまで受けるか → ③残りを何で受けるか**。リスクごとに変わるのは②の制度テーブルだけ(リスク=プラグイン)。
- 受け皿は3層: **貯蓄**(短く軽いもの+失業) / **公的制度**(全リスクの土台) / **保険**(重く長いものだけ)。診断の最終出力は「保険をいくら買うか」ではなく「どのリスクをどの層で受けるかの割り当て」。
- **言い切らないルール**(判定の3値):
  - `減らせる可能性`: 保守側(必要額レンジの上端)で計算しても現保障が上回るときだけ。**`coverage > high`**
  - `圏内・要精査`: レンジが現保障を跨ぐとき。言い切らない。**`low ≤ coverage ≤ high`（両端を含む）**
  - `不足の可能性`: 緩め(レンジ下端)に見ても現保障が届かないとき。**`coverage < low`**
  - **不等号は厳密。端ちょうどは「圏内・要精査」に入る。**
    等号で「減らせる」と言うと**減額幅0円の空主張**になり、ナイフエッジで減額を誘うことになる。
    これは「言い切らない」「安全側に倒す」という上の原則に反する。
- **世帯結論の集約ルール**（世帯は4値。**個人の判定は3値のまま変えない**）:

  | 個人判定の組み合わせ | 世帯結論 |
  |---|---|
  | 全員が `減らせる可能性` | `減らせる可能性` |
  | `不足の可能性` と `減らせる可能性` が**同居** | **`組み替えの余地`** |
  | `不足の可能性` がいて `減らせる可能性` がいない | `不足の可能性` |
  | それ以外（`圏内・要精査` を含む混在／不足なし） | `圏内・要精査` |

  - **`組み替えの余地` は世帯レベル専用の第4ラベル。** 意味は「**保障の総量は足りているが、配分がずれている**」。
    一方が過剰でもう一方が不足しているとき、**合計の保険料を増やさずに整えられる**ことを指す。
  - **個人の判定は機械的な3値のまま動かさない。** 配偶者が「200万必要・保障0」なら、それは事実であって、
    世帯の見立てがどうであれ消さない。集約は**世帯としての言い方**を決めるだけで、個人の事実を上書きしない。
  - 配偶者のいない世帯は、本人の値がそのまま世帯値になる。
  - `docs/算定テスト_10世帯.xlsx` の世帯結論10件は、この表から導出する。
  - **現行4値からの写像**（世帯レベル）:

    | 現行 | 新 | 備考 |
    |---|---|---|
    | `reducible` | `減らせる可能性` | |
    | `shortage` | `不足の可能性` | |
    | `rebalanceable` | `組み替えの余地` | |
    | `all_covered` | `減らせる可能性` | 「全員カバー済みで余剰あり」は、新3値では**減らせる側の事実** |

    上3つは **10世帯すべてで一致することを確認済み**（2026-09-21。世帯結論の期待値は1件も動かない）。
    `all_covered` だけは **corpus に該当世帯が1件も無く、正本では固定できない**。
    **合成入力による単体テストを1件だけ置く**（`docs/算定テスト_10世帯.xlsx` に合成世帯は足さない。正本は実在的世帯のまま）。
- **貯蓄軸の判定**（病気・けが・失業の行）: 死亡は「保険の過不足」で見るが、これらは
  **「貯蓄という受け皿で足りるか」**で見る。内部の3値は同じものを使い、**画面のラベルだけ行ごとに出し分ける**
  （`減らせる可能性`↔`大丈夫のめやす`／`不足の可能性`↔`備え不足の可能性`）。

  **貯蓄もレンジで比べる。** 回答が「500〜1,000万円」の幅で来ているのに点推定と比べると、
  幅で計算するという原則（§4-4）と矛盾する。両側が幅なので、保守側に対称なルールにする：

  | 条件 | 判定 |
  |---|---|
  | `貯蓄の下端 > 必要額の上端` | `大丈夫のめやす` |
  | `貯蓄の上端 < 必要額の下端` | `備え不足の可能性` |
  | それ以外（重なる） | `圏内・要精査` |

  **不等号は厳密。両端は圏内に入る**（死亡側の境界裁定と同じ理由：ナイフエッジで「大丈夫」と言わない）。
- **精度ラベル**(全リスク行に必須): `計算済み`(回答からの試算) / `制度式で概算`(公的制度の計算式どおり) / `計算未対応`(正直な空欄。根拠なく数字を置かない)。
- **AIは金額を計算しない**。自然言語what-ifでのAIの役割は「言葉→前提パラメータへの翻訳」のみ。計算は決定的エンジン。解釈した前提は必ずユーザーに表示する(プロンプトインジェクションされてもエンジンの数字は汚せない構造)。
- **登録不要のまま伴走**: アカウントの代わりに URL / PDF / .ics を渡す。リマインドはユーザー自身のカレンダーが行う。
- **売らない**: 商品名を出さない。成約手数料を受けない。だから「入らなくていい」「減らしてよい年」を利害なしに言える。
- ピッチの一文: **「万が一しか診ない計算機は、要らない。人生のリスクを、正直な精度表示つきで、全部診る。」**
- マーケ構造: **間口は広く(「うちの家計、大丈夫?」への共感)、出口は鋭く(減らせる/要精査の断言)**。


- `/result` は分割しない縦1本。上部に「現在のSTEP+判定バッジ」をスクロール追従で薄く固定。

- 実装は **390px(スマホ)基準**。1280版モックの読み替え: 滝グラフ→縦積み、段差チャート→段差3点の数字カード+ミニチャート、もしも比較表→カードのスワイプ。

## 3. 状態設計 — URLクエリの「診療記録」

- 内容: `回答(10+1問)` + `暮らし方の前提の目盛り` + `保存したもしも(変更した前提の差分のみ、名前つき)`。
- **金額そのものはURLに載せない**(既存方針の維持)。
- 4ページ(/wizard以降)が同じ器を読み書き。URLコピー=完全な保存=再開。
- 未決: 保存したもしもをURLに載せるか localStorage か。URL優先で検討(共有可能性)、肥大するなら短縮を検討。

## 4. 試算エンジン要件(本丸)

1. **シナリオを引数に取る**: `simulate(answers, assumptions, scenario)`。scenario ∈ {death, sick_short, sick_long, disability, unemployment, ...}。
2. **年次キャッシュフロー配列を返す**(総額だけでなく): 年ごとに「収入源別(遺族基礎+子加算 / 遺族厚生 / 中高齢寡婦加算 / 配偶者収入 / 傷病手当金 / 基本手当 / ...)」「支出別(生活費 / 教育費 / 整理資金 / 住居費 / ...)」。段差チャート・タイムライン・ラボ・ロードマップはすべてこの配列の別ビュー。
3. **制度式モジュール**(単純な式なので先に作る):
   - 遺族年金: 遺族基礎+子の加算(末子18歳年度末で終了、子ごとの段差)、遺族厚生(概ね報酬比例の3/4)、中高齢寡婦加算(基礎終了〜65歳)。2028年4月施行の遺族厚生見直し(子のない配偶者の有期化)は施行後の制度で計算し、注記を出す。
   - 高額療養費: 所得区分の月上限 × 月数。
   - 傷病手当金: 標準報酬日額×2/3 ×期間(待期3日、最長1年6か月)。
   - 雇用保険 基本手当: 年齢×加入期間で90〜330日。
   - 団信: 有りなら死亡シナリオの住居費を総額から除外(0円計上、理由を表示)。
4. **欠測はレンジで**: 未回答項目は幅で計算し、必要額もレンジで返す。どの項目を推定で補ったか(理由つき)を必ず返す。
5. **判定は§1の3値ルール**をエンジン側で実装(UI側で判定しない)。
6. **前提3目盛り**: 「切り詰める / いま通り / ゆとりを持つ」(名称固定。「プラン」と呼ばない)。生活費水準に作用し、全出力が連動。
7. 出典メタデータ: 各制度値に出典(機関名+年度。一次情報未確認なら旧年度値である旨)を紐づけて返す。

## 5. 画面仕様

### 5.1 LP(/)
- アイキャッチ: `誰にも聞けなかった、お金の不安に。`
- H1: `うちの家計、大丈夫なんだろうか。`
- 本文: `その問いを、誰かに口にしたことはありますか。友だちにお金の話は聞きづらい。プロに聞けば、何か勧められそう。だから、なんとなくのまま——。この診断は、誰にも会わず、名前も告げず、10問選ぶだけ。遺族年金など公的なしくみから逆算して、「大丈夫かどうか」に根拠つきで答えます。足りないのは、怖い。多すぎて払うのも、イヤ。その「ちょうどいい」まで。`
- CTA: `気軽に診断してみる — 10問、選ぶだけ` / 添え: 登録・メール不要。
- 信頼3カード: `保険を売りません` / `「分からない」でも進めます` / `言い切りません`(判定ルールをLPの約束に昇格)。
- 「診断でわかること」チップ: まず「大丈夫かどうか」/ 必要な額(幅・内訳・出典) / いまの保障との差 / 遺族年金が「いつ・なぜ」減るか / 不足が最大になる時期 / 見直しロードマップ。

### 5.2 ウィザード(/wizard)
- 既存10問 + **配偶者の年齢を1問追加**(段差の年を年齢に翻訳する要)。

### 5.3 診断結果(/result)

**玄関: リスク別健康診断表**
- 表: 項目 / 判定 / 精度 / 所見 / 詳しくリンク。
- 行: 死亡(遺されたご家族の生活) / 病気・けが短期(入院・〜3か月) / 病気・けが長期休職(がん・脳卒中・こころ、〜1年半) / 就業不能・障害(1年半超) / 失業。
- 判定・精度は§1のラベル。障害行は当面 `未診断 / 計算未対応` の正直な空欄(所見: 「根拠なく数字を置かないため、いまは空欄です」)。
- 失業行の所見: 基本手当+生活防衛資金で受ける領域、「ここは保険で備える領域ではありません」。
- **診断表の下に一行、必ず置く**：
  `病気・けが・失業の判定は、それぞれ単独で起きた場合の見立てです。同じ貯蓄を各行の受け皿として見ています。`
  理由：短期・長期・失業の3行は**同じ貯蓄を受け皿として単独で判定している**。
  判定式は変えないが、**緑が3つ並んだときに実力以上の安心を売らない**ために、重なりの前提を明示する。
- 末尾に黒帯: `万が一しか診ない計算機は、要らない。` / `人生のリスクを、正直な精度表示つきで、全部診る。それが「お金の主治医」の仕事です。`

**ページ順**（2026-09-21 オーナー確定。`result.html` の原設計に、診断表の挿入位置だけが新規）

1. **冒頭ヒーロー**（`result.html` 冒頭の移植）
2. **リスク別健康診断表**（上記のカード。位置だけここ）
3. 暮らし方の前提トグル 〜 STEP 1-4（`result.html` どおり）

**冒頭ヒーローの判定は、単一リスク（死亡・本人）ではなく §1 の世帯4値にバインドする。**
製品が5リスクに広がったぶんの唯一の改変で、レイアウト・書体・構成要素は `result.html` から変えない。
世帯4値は §1 の集約表どおり、**本人と配偶者の死亡判定（3値）から**作る。
貯蓄軸の行（病気・けが・失業）は**混ぜない** ── §1 が「保険の過不足」と「貯蓄という受け皿」を別の軸として分けているため。

**ヒーローの見出し文**

モックにある3判定は `result.html` の文をそのまま使う。

| 世帯4値 | 見出し |
|---|---|
| `減らせる可能性` | `いまの保障、{差額}ぶん 減らせる可能性があります` |
| `圏内・要精査` | `いまの保障は、必要額の幅の圏内です — ここでは言い切りません` |
| `不足の可能性` | `いまの保障では、{差額}ほど 足りない可能性があります` |

モックに無い判定は、ここで文を決めてから実装する（2026-09-21 追記）。

| 状態 | 見出し | 決めた理由 |
|---|---|---|
| `組み替えの余地` | `保障の総量は足りています。配分を組み替える余地があります` | §1 の定義（総量は足りているが配分がずれている）をそのまま文にする。**「増やす」と読ませない**ことが要点で、合計の保険料を増やさずに整えられる話だと先に言う |
| 現保障が未入力（`pending`） | `いまの保障が分からないので、過不足はまだ出していません` | FR-14。分からないことを断定しない。差額は出さず、必要額のめやすだけ出す |

**必要額が葬儀費用だけになる世帯（`death.ts` の `ample` / `not_needed`）** は、上の見出しに加えて
ヒーロー本文に1行添える。判定自体は上の表のまま（多くは `減らせる可能性` になる）。

| 状態 | 添える1行 |
|---|---|
| `ample` | `公的な年金と資産で、遺されたご家族の生活費はまかなえる見込みです。上乗せで要るのは葬儀費用だけです。` |
| `not_needed` | `扶養しているご家族がいないため、上乗せの保障は要りません。見込むのは葬儀費用だけです。` |

理由：この世帯では必要額レンジが「約200万円」の一点になる。理由を書かずに
「3,000万円に対して必要額200万円」とだけ出すと、読み手には桁を間違えた数字に見える。

**用語の衝突を作らない（2026-09-21 記録）**
「貯蓄」という語を、**同じページで2つの意味に使わない**。
診断表の「いまの貯蓄」は*いま手元にある金融資産*、死亡詳細の貯蓄推移は*死亡保険金を受け取ったあとの残高*で、
軸が違う。後者は `万一のあとの残高` と呼ぶ。
理由：金額はどちらも正しいのに、同じ名前で 750万 と 3,632万 が並ぶと、読み手には算定の誤りに見える。

**死亡の詳細(縦1本、4 STEP)**
- 冒頭ヒーロー: 判定バッジ + 見出し(差額つき) + 現保障/必要額レンジ/前提 + 「根拠を4ステップですべて示します」。
- 前提3目盛りトグル(結果側に残す唯一の「触る」要素)。
- STEP 1 あなたが答えたこと: 回答チップ(答えた=白 / 推定で補った=橙+補い方の理由1行)。注記「未回答は1つの数字で決めつけず、幅で計算して結果にも幅として残します」。
- STEP 2 もしものとき、暮らしはこうなる:
  - 左: 毎月の家計台帳(万一の翌月から/最初の10年)。入る: 遺族基礎+子加算 / 遺族厚生 / 配偶者収入 → 計。出る: 生活費(推定の幅) / 住宅ローン0円(団信)。差し引き=毎月の不足レンジ。各行に「←どの回答から」。
  - 右: **段差チャート**。公的収入の階段(実線)+配偶者収入込み(破線)+生活費(赤線)+不足の塗り。段差①②③に番号を打ち、下に「西暦(配偶者の年齢) — 何が起きて、いくらからいくらへ」を列挙。②(遺族基礎終了)=最大の崖、大学費用と重なる帯を「不足が最大」として強調。大学の学費期間を軸下にブレース表示。
  - ことばの説明(タップ切替): 遺族基礎年金=`末のお子さんが18歳の年度末(高校を出るころ)まで続く、国からの毎月の仕送り` / 遺族厚生年金 / 中高齢寡婦加算=`子育てが終わって基礎年金が止まったあとの急減をやわらげる、65歳までの上乗せ` / 団信。2028年改正の注記。
  - 接続文: 「この毎月の不足と節目の山を全部足したものが、次の必要な総額」。
- STEP 3 その積み重ねが、この金額です: 滝グラフ(総額 → ▲遺族年金 → ▲配偶者収入 → ▲貯蓄等 → =民間保険で備える額のレンジ帯)。各段に「←どの回答から」+出典チップ。住居費0円の理由行。
- STEP 4 だからこの判定: 数直線(必要額レンジ帯 + 現保障マーカー)。判定カード(3値、§1ルールの説明文)。判定ルールの明文。
  - 「あなたの判断ポイント — 3行で」: ①正念場の期間(基礎年金終了+大学) ②団信で住まいは守られている ③総額より期間の厚み(収入保障型が形として合いやすい)。→ 前提の選び直し誘導 → ラボへのCTA。

### 5.4 もしもラボ(/lab)
- **万一の時期スライダー**(年齢40〜64): 必要保障額の逓減カーブ + 現保険の水平線 + 「年々ひらく差=見直しの余地」の塗り。読み出し: 年齢(西暦)/子の年齢/必要額レンジ/現保障との差(3値の言い回し)。
- **シナリオ7種(軽→重の順、左リスト右詳細)**: 短期入院・手術(約10万〜20万) / けがで3か月(約30万〜60万) / 脳卒中・心筋梗塞で半年(約100万〜200万) / がんで1年休職(約150万〜250万) / こころの不調で休職(約100万〜300万) / 障害が残って長く働けない(計算未対応) / 死亡(本診断の値)。各詳細=使える公的なしくみ/家計への影響/備えのめやす+手段+出典。※金額は現状サンプル。実装は制度式で出せるものから順次置換し、出せないものは「まだ計算できません」を貼る。
  - 読み方の明文: 「軽く短いもしもは公的カバーと貯蓄で受けられる。保険が本当に要るのは重く長い領域だけ。医療保険を厚くする前に、まず生活費3か月分の貯蓄」。
  - 短期入院の所見に「医療保険の出番は実は小さめ」を残す(誠実さの実演)。
  - こころの所見に「手当の期限切れ(1年6か月)が正念場」を残す。
- **言葉で聞き直す(自然言語what-if)**: 入力 → AIが前提差分に翻訳 → 差分チップを表示(例: 配偶者の収入 約11万→約20万円/月) → エンジン再計算 → 差分結果。ガードレール文言を常設: `AIは金額を計算しません。あなたの言葉を前提に翻訳するだけで、計算は本編と同じ監査可能なエンジンが行います。解釈した前提は毎回このように表示します。`
- 末尾CTA: 保存とロードマップへ。

## 7. 品質検証(実装後すぐ)

1. **敵対テスト(両端)**: 片働き・子3人未就学・賃貸・貯蓄なし・団信なし → 「減らせる」が出たらロジック不良。共働き・子独立・持ち家完済・貯蓄厚 → 「不足」が出たら不良。
