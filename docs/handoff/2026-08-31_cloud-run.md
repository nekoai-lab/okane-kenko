## 8/30 にやったこと（PR #36〜#40・すべてマージ済み）

### 出力の中心を「総額の引き算」から「年次キャッシュフロー」に移した（#38 → #39）

総額の引き算は、**いちばん細い時期を平らに均してしまう**。実測した世帯では、
総額では「足りている」のに、遺族基礎年金が切れる4年間の年間収支が **+7万円**まで落ちていた。

- `projection()` は新しい数式を持ち込んでいない。既存の `calcDeath` が年ごとに計算してから
  合計に潰していたものを、**潰さずに返すだけ**。「年次の合計＝既存の総額」を不変条件テストにしたので、
  **ゴールデン10世帯の期待値は1つも動いていない**（支出・収入とも1円まで一致）
- 行構成は**日本FP協会のキャッシュフロー表に合わせた**（独自形式にしない。FPに相談したとき同じ表で話が通じる）
- 変動率は**行ごとに分ける**（生活費=物価／年金=改定率／就労=賃金／ローン・資産=固定）。
  支出だけに掛けると不足が構造的に膨らみ、「保険が要る」方向のバイアスになる。
  **初期値は全て0**で入れたので、載せ替えだけでは金額が動かない
- 画面には「いちばん細いのは◯年ごろ」と、貯蓄が底をつく年（あれば）を出す。
  残高の出発点は**金融資産＋いまの保険で受け取れる額**。保険金を無視すると底をつく年が
  実態より早く出て、いらない不安を与える＝煽りになる

### 「なぜその金額か」が見えない、への対応（#36 → #37）

8/30 の下読みで出た指摘。**指摘された2本は別モデルだった**（`3.7-flash` と `3.1-pro-preview`）ので、
**モデル選定では直らない＝画面とプロンプトの問題**として直した。

- 支出と収入の**対比グラフ**（横向き積み上げ棒2本・同縮尺）。内訳表の各行に同じ色の印を付けて対応させた
- 主グラフを**ウォーターフォール**（引き算の手続きそのものを見せる段組み）に変更。
  **当初のデザイン規定（積み上げ棒2本・グラフから引き算させない）を変えたので、
  `docs/デザイン方針.md` に理由を記録した。ADR への記載は人間の確認待ち**
- AI文：金額を押し上げている**上位2項目をこちらで計算して渡す**（AIに探させない）。
  期間のプレースホルダ `{{yearsDependent}}` `{{yearsAlone}}` を追加（年数も数値なのでAIには書かせない）
- 「0万円ほど減らせる」バグ … 結論は世帯単位なのに差額を本人単位から取っていた。
  ゴールデン全世帯で「0万円」が出ないことを回帰テストにした
- 収入が支出を上回る世帯では `range` は「足りない額」ではなく**万一直後の当座資金**。
  同じ名前で呼んでいたため文とグラフが矛盾して見えた。画面・スタブ・退避文・プロンプトの4か所を verdict 別の呼び名にそろえた

### デプロイ前の穴を2つ塞いだ（#40）

1. **params の同梱が `/api/diagnose` にしか掛かっていなかった。** `/result` と `/api/narrate` も
   `loadParams` を呼ぶので、本番だけ「パラメータが見つかりません」で落ちる。
   ローカルは cwd に params があるので気づけない
2. **検証ビルドを noindex にした。** 文面は保険業法の正式レビュー（OI-01）前のサンプルで、
   年金額も報道値（`verified:false`）。この状態のページを検索から見つかる状態にしない

## 知っておくと事故らないこと

- **auto mode では `gh pr merge` も `gcloud` 系もブロックされる。** コマンドを提示して人に打ってもらうのが早い
- **Cloud Build の第2世代トリガーはサービスアカウントの指定が必須。**
  未指定だと `INVALID_ARGUMENT` としか出ず、原因が分からない
- **鍵が弾かれる原因は、値そのものより「貼り付けで混入した不可視文字」のことがある。**
  ゼロ幅スペース・BOM・NBSP は `\s` に一致しないので空白検査をすり抜け、
  「`AIza` で始まっていない」という**的外れな理由に化ける**（8/29 の診断がまさにこれで、1往復むだにした）。
  `sanitizeApiKey` で恒久対処済み
- **セッションを跨ぐと `bakeoff-out/` の鮮度が分からなくなる。** プロンプトを触ったら回し直す
