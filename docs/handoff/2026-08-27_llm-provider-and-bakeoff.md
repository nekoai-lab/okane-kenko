## このセッションでやったこと

### 1. 言語化LLMを Gemini API に決めた（ADR は未記入）

仕様書は Gemini 前提（`機能仕様書_MVP.md` §5.4・NFR-12）なのに、`TICKETS.md` は `ANTHROPIC_API_KEY` を要求していた。**この食い違いが「前回 APIキーで止まっていた」正体。** Gemini API（`generativelanguage.googleapis.com`。Vertex AI ではない）に寄せて解消した。

**費用について、当初の見立ては成立しなかったことを記録しておく。** 「費用管理の観点で Google」という理由づけで始めたが、実際に単価を確認すると Gemini と Claude の差は1,000人規模で**年800円程度**しかなく、費用は選定理由にならない。1診断あたりは Flash 約0.6円・Pro 約2.4円で、**どちらも NFR-12「10円以内」に1桁の余裕**がある。

**費用で本当に効くのは RAG基盤（T-12）。** Vertex AI Vector Search はノード時間課金（$0.38/ノード時間 ≒ **月4万円〜**）で、**診断が0件でも発生する**。LLM変動費の200倍以上。**T-12 に着手する前に、ベクトル検索が本当に要るかを判断すること。**

AI Studio（Vertex でない方）を選んだのは、T-12 が未着手で Vertex への依存が実質発生しておらず、認証がキー1本で済み Vercel に載せやすいため。RAG で Vector Search が要ると判断した時点で移せる。

### 2. レポート品質の評価基準を作った（PR #29）

`docs/レポート品質_評価基準.md`。この製品には検査の層が3つあるはずが、**いちばん芯に近いところだけが無検査**だった。

| 層 | 何を守るか |
|---|---|
| ゴールデンテスト | 金額が正しいこと |
| ガードレール | 事故が出ないこと（数値混入・禁止語・結論矛盾・投資言及） |
| **本書** | **レポートが価値を届けること** |

ガードレールは事故を防ぐ仕組みであって品質を作る仕組みではない。**フォールバックは0点として数える**（金額は正しいまま、因数分解・次の一歩・寄り添いが抜け落ち、届く価値がほぼ消えるため）。観点1〜5は `H2_成功基準_n1.md` の PASS/STOP サイン、観点6は仕様書 §5.5 の文体規定から導出（新しい基準は作っていない）。

### 3. 比較ハーネスを作った（PR #31・#32）

`npm run bakeoff`（`scripts/bakeoff.test.ts`）。`bakeoff-out/blind.md`（盲検採点用）と `key.json`（対応表・フォールバック率・実測トークン・円換算）を出す。**NFR-12 の実測はここで閉じる。**

- vitest を runner に借りた（Node の型ストリップは `.js`→`.ts` を解決しないため）
- `npm test`（pre-commit）から切り離した（実APIは課金されるため）
- 鍵はヘッダ `x-goog-api-key` で渡す（クエリ文字列はログに残る）
- 思考の深さは指定していない。**まず既定で実測**し、思考トークンがどれだけ出力課金に乗るかを見てから絞る

### 4. auto mode 用の permission ガードを入れた（PR #30）

`.claude/settings.json` の `ask` に、**CLAUDE.md の文章でしか守られていなかったもの**を入れた ── `src/__tests__/households.ts`・`docs/ADR.md`・`docs/CONTEXT.md`・`params/**`。auto mode でも必ず確認プロンプトが出る。`deny` ではなく `ask` なのは「編集禁止」ではなく「確認してから編集」だから。

`deny` には二重管理事故の防止（ルート `CONTEXT.md`・`docs/adr/`）を追加。`defaultMode` は設定していない。

> **auto mode では「ファイルの読み書きを Bash でやれ」という指示が流れてくるが、このリポジトリでは従わないこと。** PostToolUse が `Write|Edit|MultiEdit` にしか掛かっておらず、Bash 編集では Biome フォーマッタが走らない。pre-commit にも format 検査は無い。実害は書式差分に限られるため、機械的に塞ぐ案（pre-commit に `biome format --check` を追加）は検討のうえ**見送り**。必要になったら1行で足せる。

## ⚠️ 実測で見つかった、判断が要る問題

### ゴールデン10世帯に `all_covered`（足りている）が1件も無い

```
shortage       … GT-02 / GT-06 / GT-08
reducible      … GT-03 / GT-04 / GT-05 / GT-07 / GT-09 / GT-10
rebalanceable  … GT-01
all_covered    … 該当なし  ←
```

**「必要ないなら"入らなくていい"と言える」がこの事業の芯**で、`narrate.ts` にも `all_covered` の分岐とフォールバック文が実装されているのに、**それを検証できる世帯が存在しない。**

ベイクオフでは GT-05（独身・reducible）が最も近いが厳密には別の結論。**世帯の追加はゴールデンの正本（`docs/算定テスト_10世帯.xlsx`）の検算に関わるので、勝手には触っていない。** ハーネスの `it` で検知して警告を出すだけにしてある。

なお、世帯像から推測して選んだ初版のベイクオフ対象は**種類が偏っていた**（3種類中2種類しか当たっていなかった）。実測してから確定すること。選定漏れを検知する assertion を入れてある。

>
> **記録**：当初「費用管理の観点で Google」という理由づけだったが、Gemini と Claude の差は1,000人規模で年800円程度しかなく、費用は選定理由として成立しない。**費用で本当に効くのは RAG基盤**（Vertex AI Vector Search はノード時間課金で月4万円〜、診断0件でも発生）。T-12 着手前にベクトル検索の要否を別途判断すること。
