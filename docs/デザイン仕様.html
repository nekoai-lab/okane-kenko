01 ─ 判定の色

赤はシステムエラーだけに使う ─ 保障の不足はエラーではないから

「煽らない」という芯があるので、不足を赤で出さない。減らせる（＝保険料が浮く）は利用者にとって良い知らせなので緑にする。 そして色だけで意味を伝えないため、判定は必ずアイコン・ラベル・色の3点で出す。

!足りていません ↓減らせます ✓足りています ✓保障そのものが要りません ×制度改正の反映中（診断停止）
状態色元（デジタル庁DS）この割り当てにした理由
不足している#FB5B01 / 文字 #C74700Orange-600 / 800（Warning）赤は煽りになる。不足はエラーではない
減らせる・要らない#259D63 / 文字 #197A4BGreen-600 / 800（Success）保険料が浮く＝良い知らせ
足りている#7F7F7F / 文字 #4D4D4DGray-500 / 700淡々と伝える。良くも悪くもない
システムエラー#EC0000Red-800（Error）赤はここだけ。パラメータ期限切れ・通信失敗

※ フォーカスリングは Yellow-300 #FFD43D と Black の2重構造。デジタル庁DSで「いかなる場合も変更してはいけない」と規定されているため上書きしない。

この形にした理由

決めたこと理由
色相＝支出か収入かに意味を持たせる（支出＝オレンジ系／収入＝ブルー系） 10項目を別々の色にすると識別が破綻する。カテゴリカルで安全に識別できるのは6色まで。
そもそも伝えたいのは「出ていくお金 vs 入ってくるお金」の対比
内訳は同じ色相の明度差で分け、帯の中に直接ラベルを書く 明度だけでは識別できないので、ラベルが本体。色は補助
セグメント間に2pxの背景色の隙間隣接した塗りが混ざって1つに見えるのを防ぐ
2本の棒は同じ軸・同じ0始点で上下に並べる長さをそのまま比べられる。円グラフでは比較できない
差引きの結果はヒーロー数字で別に置くグラフから引き算させない。結論を読み取らせる作業をユーザーにさせない
タイトルに対象・条件・単位を入れる「内訳」だけでは何の数字か分からない

03 ─ 同じグラフで「足りている」を出す

必要保障額の内訳（GT-01：共働き・団信あり世帯・単位：万円）

10世帯のテストでは19の死亡ケースのうち不足は2件だけでした。ほとんどの利用者はこちらの画面を見ます。 ここで煽らずに「要りません」と言い切れるかが、このプロダクトの芯そのものです。

結論

上乗せも要りません

収入・資産が支出を2,629万円上回っています。いまの保障2,000万円は、約1,800万円ぶん減らせます。
住宅ローンは団信で消え、遺族年金と奥様の収入が続くので、「何千万も足りない」は当てはまりません。

※ 遺族の就労収入を全額差し引く設計にもとづく（ADR-009）。この前提を変えると結論は変わります。
※ 年金額は令和8年度の報道値ベース（verified: false）。一次情報で確定するまで本番に出しません。
