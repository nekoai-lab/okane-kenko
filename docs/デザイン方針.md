# デザイン方針 ─ デジタル庁デザインシステムの適用

版：v1.0（2026-08-17）
参照：デジタル庁デザインシステム v2.17.0（Community）／ https://design.digital.go.jp/
実装：`src/design/tokens.css`（UI用）／ `src/design/tokens.ts`（グラフ用）

---

## なぜデジタル庁デザインシステムを使うのか

このプロダクトの芯は「売らないから、正直でいられる」。**見た目が営業資料に見えた瞬間に、その主張は弱まります。**

デジタル庁のデザインシステムを土台にする理由は3つ。

1. **中立に見える。** 公共のデザイン言語は、購買を煽らない前提で作られている。私たちが言いたいこと（「必要ないなら入らなくていい」）と、見た目の性格が一致する。
2. **アクセシビリティが最初から入っている。** カラーパレットに「白に対して3:1／4.5:1 を満たす段階」が明示されており、フォーカスリングは Yellow-300 と Black の2重構造で規定されている。自前で決めるより確実。
3. **公的制度の説明をする画面だから。** 遺族年金や高額療養費の話を、行政の資料と同じ語彙・同じ見た目で示せる。

**ただし「公的機関の資料に見せかける」ことはしない。** 出典として明記し、当社のサービスであることを明確にする。

## もう一つの参照元：Apple の公開パターン分析

色とアクセシビリティはデジタル庁DSに従う。一方で**余白・形・階層の作り方**は、Apple の公開パターン分析（[getdesign.md](https://getdesign.md/apple/design-md)）から取り入れている。

**衝突したらデジタル庁DSが勝つ。** この順序は動かさない。

### 取り入れたもの

| 取り入れたこと | 元の考え方 | このプロダクトで効く理由 |
|---|---|---|
| **UIを引かせて、主役に語らせる** | 写真が主役でUIは後退する | ここでの主役は**数字と根拠**。飾りが増えるほど「売り込み」に見える |
| **アクセント色は1つだけ** | 操作要素はすべて同じ1色。第2のブランド色を作らない | 色が増えるほど賑やかで営業的になる。中立の見え方に直結する |
| **罫線ではなく面の色で区切る** | 明／暗のタイルを交互に置く | 線が減って静かになる。長い結果画面のリズムが作れる |
| **影は1つだけ、主役にしか使わない** | 影は製品写真だけ。UIには付けない | 浮いた要素が減り、画面が落ち着く |
| **装飾のグラデーションを使わない** | 雰囲気は写真から作る | 「煽らない」という芯と一致する |
| **CTAはピル型（9999px）＋押すと少し縮む** | すべてのCTAがカプセル形 | 触れる場所が一目で分かり、反応が返る |
| **大きな数字だけ字送りを詰める**（-0.02em） | 見出しに負の字送り | ヒーロー数字が締まる。**和文の本文には掛けない** |
| **ウェイトは2つだけ**（400 / 700） | 本文400・強調600。500を使わない | 迷いが消える。中間ウェイトは和文で濁る |
| **8px基準の余白・セクション上下80px** | 8pxベース | 詰め込まないことが、そのまま落ち着いた印象になる |
| **スティッキーバーに背景ぼかし** | saturate(180%) blur(20px) | 線を引かずに層を分けられる |

### あえて取り入れなかったもの

| 取り入れなかったこと | 理由 |
|---|---|
| Apple の Action Blue `#0066cc` | 白背景で5.57:1。デジタル庁 Blue-1000 `#00118F` は**14.22:1**。余裕があるほうを採る |
| ウェイト300の「軽い」表現 | 和文は細くなりすぎる。**高齢の利用者や小さい画面で読めなくなる** |
| 本文の負の字送り | 和文は詰めると読みにくい。大きな数字と見出しにだけ掛ける |
| フォーカスリングを細い青の輪郭にする | デジタル庁DSが Yellow-300＋Black の2重構造を**変更禁止**と規定。どんな背景でも見えるほうが強い |
| 表からも罫線をなくす | 数字の表は罫線があるほうが追いやすい。面で区切るのはセクションまで |

実際の適用例は `docs/結果画面モックアップ.html`。

## トークンの構造

プリミティブ（色そのもの）とセマンティック（意味）を分ける。**UIコードはセマンティックだけを参照する。**

```
プリミティブ           セマンティック              コンポーネント
--dg-orange-600   →   --color-warning        →   不足の表示
                  →   --color-verdict-shortage
```

こうしておくと、「不足の色を変えたい」ときに1か所で済み、逆に「オレンジを使っている箇所」を後から追える。

## 色の意味 ─ このプロダクト固有の割り当て

ここがデジタル庁DSの素の定義と最も違う部分なので、理由を残す。

| このプロダクトの状態 | 使う色 | 理由 |
|---|---|---|
| **不足している** | Warning（オレンジ Orange-600 / 文字は Orange-800） | **赤を使わない。** 不足はシステムエラーではないし、赤は煽りになる。芯（煽らない）に反する |
| **減らせる・入らなくていい** | Success（グリーン Green-600 / 文字は Green-800） | 保険料が浮く＝利用者にとって良い知らせ。緑が意味と一致する |
| **足りている／上乗せも不要** | ニュートラル（Gray-500 / 文字は Gray-700） | 淡々と伝える。良いことでも悪いことでもない |
| **システムエラー** | Error（Red-800/900） | **赤はここだけ。** 制度パラメータの期限切れ、通信失敗など |

**色だけで意味を伝えない。** 判定は必ず「アイコン＋ラベル＋色」の3点セットで出す（`VERDICT_STYLE` / `GAP_STYLE`）。色覚特性のある利用者、印刷、強制カラーモードのいずれでも意味が届くこと。

**フォーカスリングは変更しない。** Yellow-300 と Black の2重構造はデジタル庁DSで「いかなる場合も変更してはいけない」と規定されている。

## 良い知らせは、良い知らせとして届ける

**当初、「足りています」を灰色で淡々と出す設計にしていた。これは「煽らない」の適用しすぎだった。**

10世帯テストで19の死亡ケースのうち不足は2件だけだった。つまり**大多数の利用者が見るのは「足りている／減らせる」画面**であり、そこが手応えのない体験だと、H2（「これなら動く」）も利用率も落ちる。レッドチーミングで「助言は体感できるお金にならない」と潰された論点への答えも、まさにここ——**安心と、浮くお金**が体感価値になる。

**正直であることと、無感情であることは別。** 中立とは払い手が成約に連動しないことであって、感情の温度の話ではない。

### ただし、褒め方を間違えると一瞬で嘘くさくなる

| やること | やらないこと |
|---|---|
| **状態を肯定する**：「もしものときも、ご家族の生活は続きます」 | ❌ **人格を褒める**：「素晴らしい備えです」 |
| **本人の選択に帰属できるものだけ、本人のものとして書く**：共働きを続けてきたこと、貯蓄を作ってきたこと | ❌ **漠然と褒める**：根拠のないお世辞になる |
| **制度のおかげの部分は、制度のおかげと書く**：「遺族年金で4,178万円が支えています」 | ❌ **制度の効果を本人の手柄にする**：読み手は違和感に気づく |
| **具体的な得を数字で出す**：「年におよそ3万円が手元に残ります」 | ❌ **診断結果を成果のように扱う**：「おめでとうございます」 |

「足りている理由の内わけ」を、**ご自身が積み上げてきたもの／公的な制度が支えている分／勤務先の制度が支えている分** の3つに分けて書く（`CreditSource`）。そのうえで「半分以上は公的な制度が支えています。ご自身の手柄というより、もともと備えは足りていたということです」と正直に言う。**これは謙遜ではなく、次に制度が変われば結論も変わるという予告になっている。**

### 落差を作らないための条件付け

褒めたあとで、制度改正やライフイベントの再診断で「足りない」と出ると、「前は大丈夫と言ったのに」になる。だから：

- `ample`（余剰が大きい）→ はっきり良い知らせとして出す
- `sufficient`（ぎりぎり足りている）→ **「いまの前提では、足りています」** と条件を必ず添え、何が変わると変わるかを示す
- どの画面のフッターにも **「これは"いまの前提での話"です」** を置く

条件を添えるのは煽りではなく、**正確さ**である。

## グラフの設計

### 1. 結果画面の主グラフ ─ 支出と収入の対比

診断の中心は「支出6,200万円 vs 収入7,300万円 → だから足りないのは0」という**因数分解**です。これが「薄くない診断」の実体なので、ここのグラフが最も重要。

- **形**：横向きの積み上げ棒を2本（支出／収入）。上下に並べて長さを直接比べられるようにする
- **色**：**色相＝支出か収入かという意味を持たせる**（支出＝オレンジ系、収入＝ブルー系）。内訳の項目は同じ色相の明度差で分け、**必ず直接ラベルを併記する**
- **なぜ10色の色分けにしないか**：カテゴリカルは6色までしか安全に識別できない。10項目を別々の色にすると識別が破綻する。「出ていくお金／入ってくるお金」という対比のほうが、そもそも伝えたいこと
- **セグメント間に2pxの背景色の隙間**を空ける（隣接した塗りが混ざって見えるのを防ぐ）
- **差引きの結果はヒーロー数字**で別に置く。グラフから引き算させない

### 2. 系列を識別するグラフ（法人ダッシュボード・分析用）

固定順のカテゴリカルパレット6色。**循環させない。**

| 順 | Light | Dark | 元 |
|---|---|---|---|
| 1 | `#264AF4` | `#4979F5` | Blue |
| 2 | `#E25100` | `#E25100` | Orange |
| 3 | `#259D63` | `#2CAC6E` | Green |
| 4 | `#C000C0` | `#DB00DB` | Magenta |
| 5 | `#6FA104` | `#6FA104` | Lime |
| 6 | `#008DA6` | `#008DA6` | Cyan |

この組み合わせは検証器（dataviz validator）で**ライト・ダークとも全6項目が合格**している——明度帯／彩度下限／色覚特性での隣接分離／通常視での隣接分離／背景とのコントラスト。

**7系列目が必要になったら、色を足さない。** 「その他」にまとめるか、グラフを分割する。

### 3. 守ること

- **軸は0始点。** 例外を使うなら誤解を招かない注記を必ず入れる
- **2軸グラフを作らない。** 単位の違う2指標は2つのグラフに分ける
- **円グラフを多用しない。** 構成比は積み上げ棒を優先（2〜3項目で直感性が要る場合のみ許容）
- **3Dグラフは使わない**
- **数値には必ず単位を付ける。** 金額は万円単位・「約」を付ける（`formatMan` / `formatRange`）
- **色は実体に従い、順位に従わない。** 絞り込みで系列数が変わっても、残った系列の色は変えない
- **文字は文字の色を着る。** 値・ラベル・凡例は本文色のまま。系列色は横に置くマークが担う
- **タイトルは対象・期間・粒度・単位を含める。** 「内訳」ではなく「必要保障額の内訳（本人が亡くなった場合・万円）」
- **表でも見られるようにする。** グラフの下に同じ数字の表を置く

## タイポグラフィ

デジタル庁DSのスケールに従う。命名は `用途-サイズ-ウェイト-行間`。

| 用途 | 使いどころ | 例 |
|---|---|---|
| **Display (Dsp)** 48〜64px | 結果画面のヒーロー数字（必要保障額） | `Dsp-48B-140` |
| **Standard (Std)** 16〜45px | 見出しと本文。既定 | `Std-16N-170` |
| **Dense (Dns)** 14〜17px | 表・補足・注記 | `Dns-14N-130` |
| **Oneline (Oln)** 14〜17px | ボタンラベル・タグなど1行で収まるもの | `Oln-16B-100` |

**本文は16px / 行間170%。** 家計と保険という重い話を読ませるので、行間を詰めない。
専門用語（団信・遺族厚生年金・高額療養費）は初出で1行注釈を付ける。

## この方針が守れているかの確認

実装のたびに以下を見る。

- [ ] 判定が「アイコン＋ラベル＋色」の3点で出ているか。色だけになっていないか
- [ ] 赤をシステムエラー以外に使っていないか
- [ ] フォーカスリングを上書きしていないか
- [ ] 数値に単位が付いているか。金額に「約」が付いているか
- [ ] グラフのタイトルに対象・単位が入っているか
- [ ] 同じ数字を表でも見られるか
- [ ] LINE内ブラウザ（iOS / Android）で崩れないか
- [ ] 文字サイズを拡大しても追従するか
