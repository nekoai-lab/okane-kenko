# 判定3値の導出記録（2026-09-21）

**2026-09-21 オーナーレビュー済み。**

判定3値・世帯4値を導入したときの監査証跡。`docs/算定テスト_10世帯.xlsx` には判定を書き込まないと決めた（ADR-021）ため、
**この文書が「判定導入時に何をどう導いたか」の記録**になる。

> `xlsx` は**金額（事実）の正本**。この文書は**規則を実在世帯に当てた結果**の記録で、
> 規則そのものの正本は `docs/redesign-spec-2026-09-21.md` §1、それを固定するのは `src/calc/verdict3.test.ts`。

## 1. 導出式

### 個人（3値）

| 条件 | 判定 |
|---|---|
| `coverage > high` | `減らせる可能性`（reducible） |
| `low ≤ coverage ≤ high` | `圏内・要精査`（uncertain） |
| `coverage < low` | `不足の可能性`（shortage） |
| `coverage` が不明 | `pending`（判定しない） |

**不等号は厳密。端ちょうどは両方とも「圏内・要精査」。**
等号で「減らせる」と言うと**減額幅0円の空主張**になり、ナイフエッジで減額を誘うことになるため。

### 世帯（4値）

| 個人判定の組み合わせ | 世帯結論 |
|---|---|
| 全員が `減らせる可能性` | `減らせる可能性` |
| `不足` と `減らせる` が同居 | **`組み替えの余地`** |
| `不足` がいて `減らせる` がいない | `不足の可能性` |
| それ以外（`圏内` を含む混在・不足なし） | `圏内・要精査` |

`組み替えの余地` は**世帯レベル専用**。意味は「保障の総量は足りているが、配分がずれている」。
**個人の判定は3値のまま動かさない**（集約は世帯としての言い方を決めるだけで、個人の事実を上書きしない）。

## 4. 残っている穴

- **`all_covered`（足りている）を出す世帯が corpus に1件も無い。**
  写像先は `減らせる可能性` と定義した（「全員カバー済みで余剰あり」は新3値では減らせる側の事実）が、
  実在世帯では確かめられない。**合成入力による単体テストを1件だけ置いて固定している**
  （`src/calc/verdict3.test.ts`）。xlsx に合成世帯は足さない。
- **`圏内・要精査` が実在世帯では GT-08 本人の1件だけ。**
  中間の判定を検証する材料が薄いので、境界（端ちょうど）は合成入力の単体テストで見ている。
