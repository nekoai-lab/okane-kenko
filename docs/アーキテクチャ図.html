お金の健康診断 ─ アーキテクチャ図 / システム設計図

2026-09-21 版 ／ 本番稼働中の構成 ／ 図の正本は docs/hackathon/*.mmd（この HTML は同じ内容を1枚にまとめたもの）

図1 ─ システム構成

秘密は Secret Manager にしかなく、制度パラメータはリポジトリにしかない

main への push で Cloud Build が lint → 型チェック → ゴールデンテスト → デプロイを通す。 params/*.yaml はコンテナに同梱されるので、実行時に外から取ってくる値ではない。 診断本体は登録不要で開けるが、運営用の承認画面だけは合言葉で閉じている。

・Firestore への認証は Application Default Credentials に委ねており、鍵をコードにも環境変数にも置いていない。

・Gemini API に渡すのは「金額を含まない文章の生成指示」だけで、算定結果の数値は渡していない。

・Slack へ送る通知にも金額を含めない（プレビューで本人以外の目に入る経路を作らない）。

図2 ─ 制度監視エージェントの信頼境界

外部の本文が金額に触れる経路が、そもそも存在しない

制度パラメータは毎年度改定され、反映漏れはエラーを出さずに誤った金額を出し続ける。 そこで一次情報を自分で巡回して差分を見つけるエージェントを置いた。ただし外部サイトを読む以上、 本文は未検証の入力である。金額の抽出は決定的なパーサが行い、本文を AI に読ませていない。

破線枠＝未検証領域 実線枠＝検証済み領域 ひし形＝検証ゲート 矢印のラベル＝何が渡るか

・取得は許可リスト内の1ホップのみ。リダイレクト先がリスト外なら本文を捨てる。ページ内のリンクも辿らない。

・取り出せない・違う金額が複数一致する・想定の幅を外れる、はすべて「取り出せなかった」として止める（推測しない）。

・エージェントは params/ を書き換える手段を持たない。できるのは承認キューに積むことだけで、値の反映は人が Pull Request で行う。

・不変条件（内訳合計・レンジ・再現性）に落ちた提案は、画面でも API でも承認できない。

図3 ─ データモデル（Firestore）

保存するのは入力の区分コードと結果の要点だけで、実額・氏名・連絡先は持たない

Phase A の「DB を持たない」を初めて崩したのは、節目に本人へ声をかけるため。 預けるものを最小にし、本人がいつでも削除できるようにしている。

・Firestore はドキュメント指向なので、図の線は外部キー制約ではなく参照の向きを表す。

・notice_log と param_watch_log には何もしなかった回も残す（沈黙も設計のうち）。

・param_proposals には、取得元URL・本文の引用・影響・全ツール呼び出しの行動ログが入る。

・制度パラメータ自体は Firestore に置かない。正本はリポジトリの params/*.yaml。
