## G. インフラ・デプロイ

**方針（2026-08-30 決定）**：ホスティングは **Cloud Run（`asia-northeast1`）**。理由は運用を gemini-case-navi と揃えられること、リージョンを明示できること（家計情報を扱うため）、ゼロスケールで診断0件の月はほぼ無料であること。**ドメインは不要**（`*.run.app` が付く）。Cloudflare は `params/*.yaml` を実行時に読む設計と噛み合わないため使わない（Workers に `fs` が無い）。

**GitHub の main に push → 自動デプロイ**（`cloudbuild.yaml`）。手元に Docker は要らない。

初回だけ必要な手順（人の操作）:

```bash
PROJECT=okane-kenko            # 新規プロジェクトを作る場合
gcloud projects create $PROJECT
gcloud billing projects link $PROJECT --billing-account=<請求先アカウントID>
gcloud config set project $PROJECT
gcloud services enable run.googleapis.com cloudbuild.googleapis.com \
  artifactregistry.googleapis.com secretmanager.googleapis.com
gcloud artifacts repositories create okane-kenko \
  --repository-format=docker --location=asia-northeast1

# 鍵は Secret Manager に置く（値をコードにも環境変数にも書かない）
printf '%s' 'AIza...' | gcloud secrets create gemini-api-key --data-file=-
```

そのうえで **Cloud Build のトリガーを作る**（GitHub 連携の承認だけはブラウザ操作）：
リポジトリ `nekoai-lab/okane-kenko`／ブランチ `^main$`／構成ファイル `cloudbuild.yaml`。
Cloud Build のサービスアカウントに **Cloud Run 管理者**・**サービスアカウント ユーザー**・**Secret Manager のシークレット アクセサー** を付ける。
