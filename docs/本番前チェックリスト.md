## G. インフラ・デプロイ

**方針（2026-08-30 決定）**：ホスティングは **Cloud Run（`asia-northeast1`）**。理由は運用を gemini-case-navi と揃えられること、リージョンを明示できること（家計情報を扱うため）、ゼロスケールで診断0件の月はほぼ無料であること。**ドメインは不要**（`*.run.app` が付く）。Cloudflare は `params/*.yaml` を実行時に読む設計と噛み合わないため使わない（Workers に `fs` が無い）。

**GitHub の main に push → 自動デプロイ**（`cloudbuild.yaml`）。手元に Docker は要らない。

### 実際の構成（2026-08-31 セットアップ完了）

| 項目 | 値 |
|---|---|
| プロジェクトID | `okane-kenko-507122`（表示名 `okane-kenko`。ID は先着で埋まっていたため数字付き） |

| ビルド用SA | `cloudbuild-deployer@okane-kenko-507122.iam.gserviceaccount.com` |

**プロジェクトIDはどこにもハードコードしていない。** `cloudbuild.yaml` は Cloud Build が渡す `$PROJECT_ID` を使う。人がIDを打つのは下記の初回コマンドだけ。

初回だけ必要な手順（人の操作。再現用に実際に打ったものを残す）:

```bash
PROJECT=okane-kenko-507122
PROJNUM=84783545243
gcloud config set project $PROJECT
gcloud services enable run.googleapis.com cloudbuild.googleapis.com \
  artifactregistry.googleapis.com secretmanager.googleapis.com iam.googleapis.com
gcloud artifacts repositories create okane-kenko \
  --repository-format=docker --location=asia-northeast1

# 鍵は Secret Manager に置く（値をコードにも環境変数にも書かない）。
# .env.local から直接パイプし、ターミナルにも履歴にも値を残さない
grep -m1 '^GEMINI_API_KEY=' .env.local | cut -d= -f2- | tr -d '\r\n' \
  | gcloud secrets create gemini-api-key --data-file=- --replication-policy=automatic
gcloud secrets versions access latest --secret=gemini-api-key | wc -c   # 39 なら正しい

# デプロイ専用SA。compute デフォルトSA（＝レガシーな「編集者」持ち）を使わない
SA="cloudbuild-deployer@${PROJECT}.iam.gserviceaccount.com"
RUNTIME="${PROJNUM}-compute@developer.gserviceaccount.com"
gcloud iam service-accounts create cloudbuild-deployer \
  --display-name="Cloud Build → Cloud Run デプロイ用"
for R in roles/run.admin roles/artifactregistry.writer roles/logging.logWriter; do
  gcloud projects add-iam-policy-binding $PROJECT \
    --member="serviceAccount:${SA}" --role="$R" --condition=None
done
gcloud iam service-accounts add-iam-policy-binding "$RUNTIME" \
  --member="serviceAccount:${SA}" --role="roles/iam.serviceAccountUser"
# 鍵を読むのはビルド側ではなく実行側
gcloud secrets add-iam-policy-binding gemini-api-key \
  --member="serviceAccount:${RUNTIME}" --role="roles/secretmanager.secretAccessor"
```

そのうえで **Cloud Build のトリガーを作る**（GitHub 連携の承認だけはブラウザ操作）：
コンソール → Cloud Build → トリガー → **リージョンを `asia-northeast1` に切り替えてから**「リポジトリを接続」。
リポジトリサービスは **第2世代（Cloud Build リポジトリ）**、リポジトリ `nekoai-lab/okane-kenko`、ブランチ `^main$`、構成ファイル `/cloudbuild.yaml`、**サービスアカウントに `cloudbuild-deployer` を指定**。

つまずきどころ:

- **第2世代はサービスアカウントの指定が必須。** 未指定だと `INVALID_ARGUMENT` としか出ず原因が分からない
- 指定SAで動かす場合、ビルドログの出力先を明示しないと失敗する。`cloudbuild.yaml` の `options.logging: CLOUD_LOGGING_ONLY` がそれ
- 「ビルドを実行する前に承認を必要とする」は **OFF**。承認のゲートは PR のマージ側にある（`main` への直接 push はフックで禁止）
- **トリガーを作った直後に手動実行しない。** `cloudbuild.yaml` が `main` に入るのは PR のマージ後で、それ以前は「構成ファイルが見つからない」で落ちる

### G-2 T-13（気づき通知）で増えた秘密と環境変数

**`cloudbuild.yaml` が参照する Secret が1つでも無いと、deploy ステップで落ちる。**
`feat/t13-watch-notify` を `main` にマージする前に、下記を済ませておくこと。
マージしてから気づくと、自動デプロイが赤で止まる。

```bash
PROJECT=okane-kenko-507122
PROJNUM=84783545243
RUNTIME="${PROJNUM}-compute@developer.gserviceaccount.com"

# 1. Slack Incoming Webhook の URL（Slack側で先に発行しておく）
#    値をターミナルに残さないよう、gemini-api-key と同じく .env.local から流し込む
grep -m1 '^SLACK_WEBHOOK_URL=' .env.local | cut -d= -f2- | tr -d '\r\n' \
  | gcloud secrets create slack-webhook-url --data-file=- --replication-policy=automatic

# 2. Cloud Scheduler と共有するシークレット
#    ここで作った値を、あとで Cloud Scheduler のヘッダにも同じものを入れる
openssl rand -hex 32 | tr -d '\n' \
  | gcloud secrets create watch-cron-secret --data-file=- --replication-policy=automatic

# 3. 読むのは実行側（ビルド側ではない）
for S in slack-webhook-url watch-cron-secret; do
  gcloud secrets add-iam-policy-binding $S \
    --member="serviceAccount:${RUNTIME}" --role="roles/secretmanager.secretAccessor"
done

# 4. Firestore（T-13 で初めて DB を持つ。既にあるか先に確認する）
gcloud firestore databases list --project=$PROJECT
gcloud firestore databases create --project=$PROJECT \
  --location=asia-northeast1 --type=firestore-native
gcloud projects add-iam-policy-binding $PROJECT \
  --member="serviceAccount:${RUNTIME}" --role="roles/datastore.user"
```

**`WATCH_BASE_URL` は Secret にしない。** 通知リンク（`/notice/{token}`）を組み立てるための公開URLで、
秘密ではないため `cloudbuild.yaml` の `--set-env-vars` で素のまま渡している。
**URLが変わったら `cloudbuild.yaml` を直す**（独自ドメインを当てるときに引っかかる）。
