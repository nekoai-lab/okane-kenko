## 2. 看板 ─ 2026-09-17 の外部イベントを踏まえて

### 何が起きたか

マネーフォワードホームが 9/17、『マネーフォワード ME』を「Apps in ChatGPT」で提供開始した。
ユーザーが接続を許可すると、銀行・カード・証券・年金・電子マネーの明細を **ChatGPTの会話から参照**でき、
支出分析・資産増減の要因分析・将来資金の検討まで対話でできる。参照専用で、認証情報は渡さない。
（出典：https://prtimes.jp/main/html/rd/p/000001675.000008962.html）

### 読み方

重なるのは「お金のデータを対話で整理する」という**入口だけ**である。
向こうは**参照で止まる**。自分で動かないし、行動もしない。ガバナンス・承認・監査は設計対象ですらない。

そして `docs/SPEC.md` の Out of Scope は、そもそも
**「データ量でマネーフォワード等に勝てないから家計最適化は扱わない」** という理由でこの線を引いていた。
9/17 の発表は、**その判断が正しかったことの外形的な裏づけ**である。方針転換は要らない。

### ここから決めること

- **捨てる（見せ場にしない）**：支出分析、資産推移、家計の可視化。データ量でもUIでも勝てない。
  デモや資料でここを厚く見せると「MEでいいのでは」と思われる。**画面にはあってよいが、主役にしない**
- **立てる（見せ場にする）**：
  1. **保障額という「判断」を、前提とレンジ付きで出す**（ざっくり答えが出ることと、前提を明示して幅で示すことは別物）
  2. **線が動いたことに気づいて教える**（＝T-13・フェーズ2b。ME も ChatGPT も、自分からは何も言ってこない）
  3. **自律と承認の境界**（診断は自律、処置は承認）
- **デモでの使い方**：3分デモの冒頭で「家計簿アプリは支出を見せるが、"いくらの保障が要るか"は答えない。そして向こうから知らせてもこない」と置く。実在サービスを名指ししなくても、審査員の頭の中にある比較対象を先回りして外せる

### 残る懸念（時間があれば潰す）

ChatGPT 側の推論で、ざっくりした必要保障額は出せてしまう。
**「出典のない概算」と「前提つき・レンジつきの算定」の違い**を、デモで意図的に見せ比べる価値がある。
`assumptions[]` と欠測数に応じたレンジ拡大は、そのための道具として既に設計に入っている。

### A. T-13 Task 11 ─ 2a を実際に動かす（最優先・人手を含む）

動いていない実装は提出物にならない。手順は `2026-09-14_watch-notify-plan.md` Task 11 にある。

1. `npm test && npm run typecheck && npm run lint` を**本人のMacで** green 確認
2. Firestore 有効化 → Cloud Run 実行SAに `roles/datastore.user`
3. Slack Incoming Webhook 発行 → `.env.local` に3変数（`SLACK_WEBHOOK_URL` / `WATCH_CRON_SECRET` / `WATCH_BASE_URL`）
4. 同意フロー → ウォッチャー実行 → 着地画面 → 削除、の一連をローカルで通す
5. **マージ前に** Secret Manager に `slack-webhook-url` と `watch-cron-secret` を作り、実行SAに accessor を付ける（[`docs/本番前チェックリスト.md`](../本番前チェックリスト.md) §G-2）。
   `cloudbuild.yaml` が参照する Secret が1つでも無いと deploy が落ちるので、**順番を逆にしない**
6. PR → `main` マージ（＝自動デプロイ）。Cloud Build は `^main$` にしか反応しないので、ブランチを push しただけでは何も起きない
7. Cloud Scheduler ジョブ `watch-notify-weekly` を作成

**完了の合図**：Slack に通知が届き、リンクから `/notice/{token}` → `/result` まで実機で繋がる。

### B. フェーズ2b ─ 制度側の自律監視（②を埋める本丸）

**まず設計を書く**（`docs/hackathon/2026-09-2x_param-watch-design.md`）。実装前に以下を決める。

- **対象パラメータを1つに絞る**（候補：遺族基礎年金）。広げない
- **観察**：許可リスト内の一次情報のみ取得。取得した本文は `untrusted` として扱う
- **判断**：現行 `params/*.yaml` との差分を抽出 → **候補値でゴールデンテスト10世帯70件を自分で実行** →
  「結論が変わる世帯が何件あるか」で重要度を決める（差分があっても結論が変わらなければ静かにする）
- **行動**：版案＋影響レポート＋根拠URL＋行動ログを**承認キューに積むだけ**。`params/` には触れない
- **承認画面**：GT不合格なら承認ボタンを出さない
- **監査ログ**：全ツール呼び出し（入力・出力・所要時間・判断理由）を時系列で読める形に

**守る線**：ここでも CLAUDE.md の責務境界を崩さない。**AIは金額を作らない**。
数値は `src/calc` と `params/` だけが持ち、AIが決めるのは「何を確かめるか・いつ動くか・誰に何を渡すか」だけ。

**完了の合図**：1周まわして承認待ちが1件画面に出る。承認しない限り `params/` が1バイトも変わらないことを画面で示せる。

## 5. Claude Code への申し送り

- **`CLAUDE.md` を必ず先に読む。** 特に「絶対にやらないこと」6項目と責務境界の表
- **金額は `src/calc/` でしか作らない。** AIに数値を書かせず、プレースホルダを差し込む方式を崩さない

- **環境変数は `.env.example` に名前・用途・取得先だけ書き、実値は人間に依頼する**
- commit 前に lint / typecheck / `npm test` が自動で走り、1つでも落ちると commit できない
- `git push` は人間が実行する（エージェントのシェルからは GitHub の認証が通らない）
- **ハンドオフを書いたら `docs/STATUS.md` も必ず一緒に更新する**（薄い索引に保つ）
