## 3. 設計の裁定（決め打ちで進める）

- **ストレージは Firestore**（`approvals`／`audit_runs` の2コレクション。原計画どおり、審査でも説明が通る構成）
- **ツールは読み書き分離を厳守**
  - 読み取り＝`fetch_official_source`（ドメイン許可リスト・本文は untrusted タグ）／`read_params`／`run_checks`（core に POST の検算口を1本足し、GT＋statutory を HTTP 越しに実行）
  - 書き込み＝`propose_param_version`（承認キューに積むだけ）
- **承認→適用の経路**：提案には適用可能な完全な yaml 差分を含める。承認ボタンは「approved」を記録するだけで、params の実変更はリポジトリへのコミット（push は人間）。
  「承認しない限り params が1バイトも変わらない」を画面と git 履歴の両方で示せる形 ── Claude が直してコミット・本人が push、という運用とも一致
- **エージェントの判断基準は既にあるものを使う**：params の sources（`effectiveFrom`・`expires`・`pendingChange`・`revisionCycle`）が「何を疑うべきか」の台帳。新しい判断ルールを発明しない
