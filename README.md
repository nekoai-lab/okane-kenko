## 設計上の要点

**1. 金額を作るのはコードだけ。AIは翻訳しかしない。**
「必要ないなら入らなくていい」と根拠つきで言い切れることが信頼の証明である以上、その根拠は後から再現できなければならない。だから数値は決定的な計算式で作り、AIには数値を書かせない（プレースホルダだけを書かせ、クライアントが差し込む）。

**2. 制度改正には「壊れたら止まる」で対応する。**
遺族年金額は毎年度改定され、高額療養費は2026年8月・2027年8月に段階施行される。反映漏れはエラーを出さず、誤った金額を出し続ける形で現れる。だから期限切れの中核パラメータでは診断を停止する。

**3. 算定エンジンは外部サービスに依存しない純粋関数。**
Vercel → Cloud Run とインフラを移しても、金額を決めるロジックとテストはそのまま動く。

## この診断が返す結論

10世帯の試算で分かったこと ─ **不足は2件、減額余地ありが12件**（合計約1億2,000万円）。
遺族年金は多くの人が思うより手厚く、共働き世帯ではほぼ充足する。
つまり実際に起きている問題は「保障が足りない」ではなく **必要のない保障に払い続けている** こと。

- 年金額は令和8年度の**報道値ベース**（`verified: false`）。一次情報で確定させるまで本番に出さない

- 10世帯は**架空の世帯**。実在世帯で未検証（特にGT-08が充足になるのは直感に反する）
